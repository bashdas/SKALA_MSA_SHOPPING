# MSA E2E 테스트

## 목적

`user-service`와 `order-service`를 실제로 함께 실행해 회원가입, JWT 인증, 상품 및 주문, 포인트 차감·환불, 주문 소유권, 재고 원상복구까지 서비스 간 전체 흐름을 검증한다. 운영 코드는 변경하지 않는다.

## 실행 전제

- macOS 또는 일반 Linux의 Bash 환경
- `bash`, `curl`, `java`
- JSON 파싱용 `jq` 또는 `python3` 중 하나
- 8081과 8082 포트가 비어 있어야 함
- 각 서비스의 Gradle Wrapper가 실행 가능해야 함(시스템 Gradle은 불필요)

## 실행

모노레포 루트에서 다음 명령을 실행한다.

```bash
./scripts/msa-e2e-test.sh
```

스크립트는 `user-service`를 8081, `order-service`를 8082에서 백그라운드로 실행한다. 두 서비스가 준비될 때까지 최대 120초 동안 polling하며 무한 대기하지 않는다.

두 서비스는 JWT 서명과 검증에 같은 대칭키를 사용해야 하므로, 스크립트가 실행할 때마다 임시 E2E 전용 `JWT_SECRET`을 만들고 두 프로세스에 동일하게 전달한다. 운영 secret은 저장하거나 사용하지 않는다.

## 검증 시나리오

1. 두 서비스 실행 및 준비 상태
2. 고객 A 회원가입, 초기 10,000포인트와 로그인/JWT
3. 정수 가격 상품 두 개 등록 및 조회
4. 미인증 주문의 401/`UNAUTHORIZED`
5. 신규 주문, 주문 내용, 포인트 차감, 재고 차감
6. 기존 주문 수량 누적, 동일 주문 ID, 증가분 포인트 차감
7. 고객 B의 주문 조회·부분 취소·전체 취소 차단과 무변경 확인
8. 부분 취소, 일부 포인트 환불, 일부 재고 복구
9. 전체 취소, 전액 환불, 주문·포인트·재고 원상복구

H2 인메모리 DB와 `create-drop` 설정을 사용하므로 서비스를 다시 실행할 때마다 데이터가 초기화된다.

## 실패 로그

실패하면 마지막 출력에 `/tmp` 또는 시스템 임시 디렉터리 아래의 `shopping-msa-e2e.*` 경로가 표시된다. 그 안의 `user-service.log`, `order-service.log`, PID 및 마지막 HTTP 응답을 확인할 수 있다. 성공하면 이 임시 디렉터리를 자동 삭제한다. 성공·실패와 관계없이 trap이 두 서비스와 자식 프로세스를 종료한다.

## 검증하지 않는 범위

- 실제 운영 DB
- 네트워크 분리 환경
- Circuit Breaker
- Service Discovery
- 메시지 기반 Saga
- 다중 인스턴스 환경
- 부하 테스트
